Código y modelos matemáticos de Guaquirí Connect

Universidad del Norte · Matemáticas discretas · Dónde está cada modelo y el código que lo calcula

Este documento explica el programa que reparte la señal desde la casa principal de Guaquirí (corregimiento de Pedraza, Magdalena) hacia el resto de viviendas. La matemática no está en los botones ni en los pagos. Está en la carpeta src/math/ y se ejecuta desde src/context/NetworkContext.tsx. El peso del grafo es la distancia en metros.

1. Qué problema resuelve

Instalar Starlink en una sola casa no comunica al corregimiento. Falta decidir qué casas se unen entre sí. El programa recibe coordenadas, mide la distancia geodésica de cada par y se queda con un conjunto de enlaces que conecta todos los puntos, sin ciclos, y con la menor longitud total.

La casa principal es el único punto confirmado. Sale de Google Earth: 10°06'56,56" N y 74°55'28,23" O, a 11 m de elevación. La zona se toma como punto de partida porque el mapa de cobertura de Starlink (SpaceX) muestra servicio ahí. Los otros 23 puntos son una red de prueba alrededor de ese origen: 3 repetidores, 12 viviendas del núcleo y 8 viviendas alejadas. No son un censo casa por casa.

2. Recorrido, en el orden en que corre el programa

  1. Vértices. Lee la casa principal y los desplazamientos en metros al este y al norte. Archivo: src/data/community.ts.
  2. Distancia. Mide cada par con Haversine. Archivo: src/math/spatial.ts, función geodesicDistanceMeters.
  3. Medio. Si la distancia es de hasta 100 m, el enlace es cable UTP. Si pasa de 100 m, es un radio de 5 GHz. Función selectLink.
  4. Árbol. Kruskal o Prim eligen 23 enlaces: la red conexa más corta. Archivos kruskal.ts y prim.ts.
  5. Camino. Si se elige una vivienda, Dijkstra marca cómo llegar desde la antena. Archivo dijkstra.ts.

No hay una tabla de distancias escrita a mano. Si se agrega una casa con un clic en el mapa, los pasos 2 a 5 se vuelven a correr.

4. Vértices: el conjunto V

Archivo src/data/community.ts. La casa principal se llama gw-principal. Su coordenada se escribe en grados decimales a partir de grados, minutos y segundos. El resto de viviendas no trae latitud propia: cada una tiene un desplazamiento east (metros al este) y north (metros al norte). La función offsetMeters, en spatial.ts, convierte ese desplazamiento en una coordenada. Si el desplazamiento es cero, el punto sigue siendo la casa principal.

export const GATEWAY_ID = "gw-principal";

Los tres repetidores quedan así, medidos desde la casa principal: 55 m al norte; 60 m al este y 10 m al sur; 45 m al oeste y 35 m al sur. Las 12 viviendas del núcleo están a menos de 50 m. Las 8 periféricas están entre 190 m y 221 m. Esas cifras son la forma de la red de prueba, no un levantamiento.

// spatial.ts — pasa de "tantos metros al este y al norte" a latitud y longitud
export function offsetMeters(origin, eastMeters, northMeters) {
  const distanceMeters = Math.hypot(eastMeters, northMeters);
  if (distanceMeters === 0) return origin;          // la casa principal
  const bearing = Math.atan2(eastMeters, northMeters) * 180 / Math.PI;
  // destination avanza esa distancia sobre la esfera, desde el origen
  return destino(origin, distanceMeters, bearing);
}

5. Distancia: el peso w(e) = d(e)

Archivo src/math/spatial.ts. La distancia no se lee en línea recta sobre el dibujo. geodesicDistanceMeters pide a la librería Turf la fórmula de Haversine sobre la esfera. El resultado queda en metros. Esa longitud es el peso con el que se compara un enlace contra otro.

// spatial.ts — d(u, v) en metros. No es distancia del plano del mapa.
export function geodesicDistanceMeters(a, b) {
  return distance(
    point([a.lng, a.lat]),
    point([b.lng, b.lat]),
    { units: "meters" }
  );
}

La misma distancia decide el medio. Ethernet de exteriores, en el criterio del programa, se usa hasta 100 m. Pasado ese valor, el tramo se marca como radio de 5 GHz. selectLink no inventa otra medida: solo clasifica d(e).

// spatial.ts
export const UTP_MAX_METERS = 100;

export function selectLink(distanceMeters) {
  if (distanceMeters <= 100) {
    return { type: "utp_outdoor", wireless: false };  // cable
  }
  return { type: "ptp_5ghz", wireless: true };        // radio
}
El archivo también calcula un costo en pesos: 1.200 COP por metro de cable, y 280.000 COP fijos si el enlace es radio. Kruskal ordena primero por ese costo y, si empatan, por la distancia. En esta red todo cable es más corto que todo radio, así que el árbol que sale es el de menor longitud. El costo es una lectura posterior, por si el modelo pasa a un presupuesto. No es la pregunta del curso.

Dijkstra no usa ese costo. Usa attenuationUnits, una penalización que también crece con los metros. En cable suma 0,04 por metro. En radio suma 12 por el salto y después 0,02 por metro. Un cable de 23 m queda cerca de 0,9. Un radio de 190 m queda cerca de 15,8. No es una medición de señal en campo: sirve para comparar caminos dentro del programa.

// spatial.ts — peso del camino. Sigue siendo función de la distancia.
export function attenuationUnits(edge) {
  if (edge.type === "ptp_5ghz") {
    return 12 + edge.distanceMeters * 0.02;   // radio
  }
  if (edge.type === "fiber") {
    return 0.5 + edge.distanceMeters * 0.005; // la malla generada no produce fibra
  }
  return edge.distanceMeters * 0.04;          // cable UTP
}

6. El grafo G = (V, E)

Archivo src/math/graph.ts. buildCandidateEdges une todos los pares de vértices. No descarta un enlace antes de medirlo, porque podría ser el tramo corto que conecta un grupo. Con 24 vértices el número de aristas es el de un grafo completo:

|E| = 24 × 23 / 2 = 276.

De esas 276, 124 quedan en cable (100 m o menos) y 152 quedan en radio.

// graph.ts — malla candidata. Cada par se mide y se clasifica.
export function buildCandidateEdges(nodes) {
  const edges = [];
  for (let i = 0; i < nodes.length; i++) {
    for (let j = i + 1; j < nodes.length; j++) {
      const distanceMeters = geodesicDistanceMeters(nodes[i], nodes[j]);
      const link = selectLink(distanceMeters);
      edges.push({
        id: [nodes[i].id, nodes[j].id].sort().join("__"),
        source: nodes[i].id,
        target: nodes[j].id,
        distanceMeters,          // este es el peso que importa
        type: link.type,         // "utp_outdoor" o "ptp_5ghz"
        costCOP: link.costCOP,   // lectura en pesos, no el objetivo
        inMST: false             // todavía no se sabe si entra al árbol
      });
    }
  }
  return edges;
}

La clase RuralGraph ofrece dos vistas del mismo grafo, que es lo que pide la teoría del curso:

  • Lista de adyacencia. Para cada vértice, la lista de vecinos y la arista que los une. Prim y Dijkstra recorren esta lista.
  • Matriz de adyacencia. Una tabla de 24 × 24. La casilla (i, j) guarda la distancia entre esos dos vértices. La diagonal es 0 porque no hay lazo. La matriz es simétrica: ir de A a B mide lo mismo que ir de B a A. El panel «Modelo matemático» la muestra.

maxPortsFor limita cuántos enlaces del árbol puede recibir un equipo: 8 en la antena y en cada repetidor, 4 en cada vivienda. En la red de prueba el árbol no llena ese cupo: la casa principal queda con grado 2 y ninguna vivienda pasa de grado 3. Si el cupo fuera menor, la regla que salta la arista ya no garantiza el árbol más corto.

// graph.ts — tope de puertos. No cambia la distancia; limita el grado.
export function maxPortsFor(node) {
  if (node.type === "gateway") return 8;   // casa principal
  if (node.type === "repeater") return 8;
  return 4;                                 // vivienda
}

summarizeEdges suma, de un conjunto de aristas, tres cosas: cuántas son, cuántos metros miden en total y cuánto sumarían en pesos. countComponents dice si esas aristas dejan la red en una sola pieza o en varias. El árbol válido de esta red deja una sola componente.

7. Kruskal: el árbol de menor longitud

Archivo src/math/kruskal.ts. Un árbol de 24 vértices tiene 23 aristas, conecta todos los puntos y no tiene ciclos. Entre todos esos árboles, Kruskal busca el de menor longitud total. El problema, escrito corto, es:

T* = el árbol T que minimiza la suma de d(e), con e en T.

El algoritmo ordena las 276 aristas de menor a mayor. Recorre la lista una sola vez. Una arista entra si sus dos extremos siguen en grupos distintos. Si ya están en el mismo grupo, la arista cierra un ciclo y se descarta. Esa es la propiedad de ciclo: en un ciclo, el lado más largo no hace falta para el árbol mínimo, porque se puede reemplazar por otro lado del ciclo y la suma baja.

// kruskal.ts — ordenar y aceptar solo si no hay ciclo
const sorted = [...edges].sort((a, b) =>
  a.costCOP - b.costCOP ||                 // entre cables, esto sigue a los metros
  a.distanceMeters - b.distanceMeters ||   // desempate: la más corta
  a.id.localeCompare(b.id)                 // desempate final, para que no cambie
);

const sets = new DisjointSet(nodeIds.length);  // un grupo por vértice
const chosen = [];

for (const edge of sorted) {
  const left = index.get(edge.source);
  const right = index.get(edge.target);

  // Propiedad de ciclo: si ya están unidos, esta arista sobra.
  if (sets.find(left) === sets.find(right)) continue;

  // Tope de puertos, solo si está activado. Si no, esta parte no corre.
  if (options?.maxDegree) {
    if (degree.get(edge.source) >= limit(edge.source)) continue;
    if (degree.get(edge.target) >= limit(edge.target)) continue;
  }

  sets.union(left, right);                 // fusiona los dos grupos
  chosen.push({ ...edge, inMST: true });  // esta arista sí entra al árbol
}

Ejemplo con datos de la red. La casa principal y la vivienda 01 están a 22,8 m. La vivienda 01 y la vivienda 05 están a 22,8 m. Esas dos entran, porque unen grupos distintos. La casa principal y la vivienda 05 están a 38,0 m en línea directa. Cuando Kruskal llega a esa tercera arista, la vivienda 05 ya está unida a la casa pasando por la vivienda 01, así que los 38,0 m se rechazan. El ciclo casa–01–05 pierde su lado más largo.

Union-Find, en el mismo archivo

La clase DisjointSet responde una sola pregunta: ¿estos dos puntos ya quedaron en el mismo grupo? Al empezar hay 24 grupos, uno por vértice. Cada vez que una arista entra al árbol, union fusiona dos grupos.

  • find. Sube hasta la raíz del grupo. De paso, deja a los vértices apuntando directo a esa raíz (compresión de caminos), para que la próxima consulta sea más corta.
  • union. Cuelga el grupo más bajo del más alto (unión por rango). Si los dos tienen la misma altura, uno pasa a ser raíz y su rango sube en uno.

Kruskal no usa esta estructura para medir. La usa solo para no aceptar un ciclo. El tiempo del algoritmo lo pone el ordenamiento de las 276 aristas: O(|E| log |E|).

Resultado: 23 aristas y 870,7 m. De esos metros, cerca de 443 m son cable (tramos de 15,3 m a 32,0 m) y cerca de 428 m son tres radios, uno por grupo lejano. La casa principal solo suelta dos cables directos, de 22,8 m y 28,8 m.

8. Prim: el mismo árbol, creciendo desde la antena

Archivo src/math/prim.ts. Prim no ordena toda la lista de entrada. Hace crecer un solo árbol desde la casa principal, que es el único equipo ya decidido. En cada paso toma la arista más corta que sale de lo ya conectado hacia un vértice que todavía está fuera. Esa es la propiedad de corte: a través del corte entre lo alcanzado y lo que falta, una arista de longitud mínima pertenece a algún árbol mínimo.

// prim.ts — inTree empieza solo con la antena
export function primMST(nodes, edges, startId, maxDegree) {
  const adjacent = new RuralGraph(nodes, edges).adjacencyList();
  const inTree = new Set([startId]);     // startId = "gw-principal"
  const heap = new MinHeap(/* compara por costo y luego por metros */);

  function pushFrom(id) {
    for (const link of adjacent.get(id) ?? []) {
      if (!inTree.has(link.neighborId)) {
        heap.push({ edge: link.edge, next: link.neighborId });
      }
    }
  }

  pushFrom(startId);  // entran a la cola las aristas que salen de la casa principal
  const chosen = [];

  while (heap.size > 0 && inTree.size < nodes.length) {
    const item = heap.pop();                 // la más corta que cruza el corte
    if (!item || inTree.has(item.next)) continue;

    inTree.add(item.next);                    // esa casa ya quedó en el árbol
    chosen.push({ ...item.edge, inMST: true });
    pushFrom(item.next);                      // ahora se ofrecen las aristas de esa casa
  }
  return chosen;
}

La cola es el montículo de src/math/heap.ts. Siempre entrega el menor. El programa no hace decrease-key: si una arista mejora, entra otra copia y la copia vieja se ignora al salir. Por eso el costo de tiempo sigue en O(|E| log |E|).

La primera arista de toda la malla mide 15,3 m y une el repetidor norte con la vivienda 06. Kruskal la acepta de entrada. Prim, como arranca en la antena, todavía no la ve. La arista más corta que sale de la casa principal mide 22,8 m y llega a la vivienda 01: esa es la primera del árbol de Prim. El orden de aceptación cambia. La longitud total no: en este grafo conexo los dos algoritmos dan 870,7 m y 23 aristas.

En la pantalla se puede cambiar de Kruskal a Prim. NetworkContext elige la función. Sin tope de puertos, las dos longitudes coinciden.

9. Dijkstra: el camino desde la casa principal

Archivo src/math/dijkstra.ts. El árbol dice qué enlaces se construyen. Otra pregunta es cómo se llega, desde la antena, hasta la vivienda que se eligió. Dijkstra resuelve el camino de menor peso cuando todos los pesos son positivos. Aquí el origen es gw-principal y el peso de cada arista es attenuationUnits, no el costo en pesos.

// dijkstra.ts
export function dijkstra(nodes, edges, sourceId, weight) {
  const adjacent = new RuralGraph(nodes, edges).adjacencyList();
  const dist = new Map();   // penalización acumulada desde la antena
  const prev = new Map();   // de qué casa se llegó, y por cuál arista

  for (const node of nodes) {
    dist.set(node.id, Infinity);
    prev.set(node.id, null);
  }
  dist.set(sourceId, 0);     // la casa principal parte en 0
  const heap = new MinHeap((a, b) => a.d < b.d);
  heap.push({ id: sourceId, d: 0 });

  while (heap.size > 0) {
    const current = heap.pop();
    // Si esta copia de la cola ya quedó vieja, se ignora.
    if (current.d > dist.get(current.id)) continue;

    for (const link of adjacent.get(current.id) ?? []) {
      const next = current.d + weight(link.edge);  // suma la penalización del tramo
      if (next < dist.get(link.neighborId)) {
        dist.set(link.neighborId, next);
        prev.set(link.neighborId, {
          nodeId: current.id,
          edgeId: link.edge.id
        });
        heap.push({ id: link.neighborId, d: next });
      }
    }
  }
  return { dist, prev };
}

Como la penalización es positiva, la primera vez que una vivienda sale de la cola su valor queda fijo. No hace falta volver a calcularla. reconstructPath sigue los predecesores desde la vivienda hasta la antena y da la lista de casas. pathEdges da la lista de aristas de ese mismo camino. El tiempo, con el montículo y copias repetidas, es O((|V| + |E|) log |V|).

Dijkstra no recorre solo el árbol. En NetworkContext se llama con las 276 aristas candidatas, no con las 23 del árbol. Por eso el camino marcado hasta una vivienda lejana puede ser el radio directo, aunque ese radio no esté en el árbol. El árbol prefiere un solo radio por grupo, porque así la suma de metros es menor. El camino de menor penalización prefiere no atravesar varias casas si un salto directo suma menos. Las dos cuentas usan la distancia. No responden la misma pregunta, y la pantalla las muestra por separado: el árbol en el mapa, y el camino cuando se toca una vivienda.

Ejemplo. La vivienda alejada que está a 190,2 m de la antena obtiene, por el radio directo, 12 + 0,02 × 190,2 = 15,8. El camino por el árbol es más largo en esa penalización, porque primero recorre el núcleo y después cruza un solo radio de grupo. Para decidir qué enlaces existen, manda el árbol. Dijkstra sirve para no presentar ese árbol como si también fuera el camino de menor penalización.

12. Cómo contarlo en la sustentación

  1. El problema es llevar la señal desde la casa principal hasta las otras viviendas de Guaquirí. La cobertura de Starlink justifica la antena en esa casa. Google Earth da la coordenada.
  2. El programa arma un grafo de 24 vértices y 276 aristas. El peso de cada arista es su distancia en metros.
  3. Hasta 100 m el enlace es cable. Después es radio. Eso clasifica el medio; no reemplaza la distancia.
  4. Kruskal y Prim construyen el árbol de menor longitud: 23 aristas y 870,7 m. Kruskal ordena todas las aristas. Prim crece desde la antena. En esta red la longitud coincide.
  5. Dijkstra, con una penalización que crece con los metros, muestra el camino desde la casa principal hasta la vivienda que se toca. Corre sobre toda la malla, así que ese camino no tiene que ser el del árbol.
  6. Si más adelante se reemplazan las 23 casas de prueba por un levantamiento, se cambian las coordenadas. Kruskal, Prim y Dijkstra se quedan igual.
