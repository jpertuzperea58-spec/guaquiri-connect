Dónde está cada modelo en el código

La interfaz dibuja el mapa. La matemática está en src/math/ y se ejecuta desde NetworkContext.tsx. El peso del grafo es la distancia en metros entre la casa principal y el resto de puntos.

Recorrido del programa

Cada vez que cambia una casa, el programa repite estos cinco pasos. No hay una tabla de distancias escrita a mano.

1. VérticesCasa principal confirmada en Google Earth. Las otras 23 son una red de prueba.
2. DistanciaHaversine entre cada par. Eso es \(d(u,v)\) en metros.
3. MedioHasta 100 m, cable. Más de 100 m, radio de 5 GHz.
4. ÁrbolKruskal o Prim eligen 23 enlaces: la red más corta sin ciclos.
5. CaminoAl elegir una vivienda, Dijkstra marca cómo se llega desde la antena.

1. Vértices \(V\)

Datos

La casa principal sale de Google Earth: 10°06'56,56" N, 74°55'28,23" O. El código la guarda en grados decimales. Los demás puntos se mueven desde ese origen unos metros al este y al norte.

Hay 1 antena, 3 repetidores y 20 viviendas. \(|V| = 24\).

Archivo

src/data/community.ts

offsetMeters en spatial.ts convierte esos metros en latitud y longitud. Si el desplazamiento es 0, el punto es la casa principal.

2. Distancia \(d(u,v)\)

No se mide en línea recta sobre el dibujo del mapa. geodesicDistanceMeters pide a Turf la fórmula de Haversine, en metros.

// spatial.ts — peso real del grafo: metros entre dos coordenadas
export function geodesicDistanceMeters(a, b) {
  return distance(point([a.lng, a.lat]), point([b.lng, b.lat]), {
    units: "meters",
  });
}

Umbral de 100 m

selectLink no cambia la distancia. Solo decide el medio: cable si el tramo cabe en Ethernet, radio si no.

// spatial.ts — el medio depende de la distancia, no al revés
export const UTP_MAX_METERS = 100;

export function selectLink(distanceMeters) {
  if (distanceMeters <= 100) {
    return { type: "utp_outdoor", wireless: false }; // cable
  }
  return { type: "ptp_5ghz", wireless: true };       // radio 5 GHz
}
El archivo también guarda un costo en pesos, proporcional a los metros en el cable y fijo en el radio. Kruskal ordena por ese costo y, si empatan, por la distancia. Como todo cable de esta red es más corto que todo radio, el árbol que sale es el de menor longitud.

Penalización para el camino

Dijkstra no minimiza plata. Suma una penalización que crece con los metros: 0,04 por metro de cable, o 12 más 0,02 por metro de radio.

// spatial.ts — peso de Dijkstra. Sigue siendo función de la distancia.
export function attenuationUnits(edge) {
  if (edge.type === "ptp_5ghz") return 12 + edge.distanceMeters * 0.02;
  if (edge.type === "fiber")    return 0.5 + edge.distanceMeters * 0.005;
  return edge.distanceMeters * 0.04; // UTP
}

3. El grafo \(G = (V, E)\)

buildCandidateEdges une todos los pares. Con 24 vértices eso es \(\binom{24}{2} = 276\) aristas. Cada una guarda la distancia, el medio y si ya entró al árbol.

// graph.ts — la malla candidata es el grafo completo
export function buildCandidateEdges(nodes) {
  const edges = [];
  for (let i = 0; i < nodes.length; i++) {
    for (let j = i + 1; j < nodes.length; j++) {
      const distanceMeters = geodesicDistanceMeters(nodes[i], nodes[j]);
      const link = selectLink(distanceMeters); // cable o radio
      edges.push({
        source: nodes[i].id,
        target: nodes[j].id,
        distanceMeters,
        type: link.type,
        inMST: false,
      });
    }
  }
  return edges; // |E| = 276
}
Matriz

RuralGraph.adjacencyMatrix() es simétrica. La diagonal vale 0 porque no hay lazo. El panel «Modelo matemático» la muestra.

Lista

adjacencyList() guarda, para cada casa, sus vecinos. Prim y Dijkstra recorren esa lista, no la matriz.

maxPortsFor limita el grado en el árbol: 8 enlaces en la antena y en cada repetidor, 4 en cada vivienda. En esta red el árbol no llega a ese tope.

4. Kruskal · árbol más corto

Ordena las aristas de menor a mayor. Acepta la siguiente solo si sus extremos todavía no están conectados. Si ya lo están, la arista cierra un ciclo y se descarta. Esa es la propiedad de ciclo.

// kruskal.ts — el orden es el modelo: primero la arista más corta
const sorted = [...edges].sort((a, b) =>
  a.costCOP - b.costCOP ||          // entre cables, esto sigue a los metros
  a.distanceMeters - b.distanceMeters ||
  a.id.localeCompare(b.id)
);

for (const edge of sorted) {
  if (sets.find(left) === sets.find(right)) continue; // cierra ciclo: se rechaza
  sets.union(left, right);                             // une las dos componentes
  chosen.push({ ...edge, inMST: true });
}
Union-Find

La clase DisjointSet, en el mismo archivo, responde «¿estos dos puntos ya quedaron en el mismo grupo?». find comprime el camino. union cuelga el árbol más bajo del más alto. Kruskal la usa solo para no aceptar un ciclo.

Resultado en la red de prueba: 23 aristas y 870,7 m. Una estrella desde la casa principal, también de 23 aristas, mide 2.247,4 m.

5. Prim · el árbol crece desde la antena

No mira primero la arista más corta de todo el mapa. Empieza en gw-principal y, en cada paso, toma la arista más corta que sale de lo ya alcanzado hacia una casa que todavía está fuera. Esa es la propiedad de corte.

// prim.ts — el conjunto inTree empieza solo con la casa principal
const inTree = new Set([startId]); // startId = "gw-principal"
pushFrom(startId);                  // mete a la cola las aristas que salen de la antena

while (heap.size > 0 && inTree.size < nodes.length) {
  const item = heap.pop();         // la más corta que cruza el corte
  if (inTree.has(item.next)) continue;
  inTree.add(item.next);
  chosen.push({ ...item.edge, inMST: true });
  pushFrom(item.next);              // ahora también salen aristas desde la casa nueva
}

La primera arista de Prim es casa principal → vivienda 01, a 22,8 m. La primera de Kruskal es otra: repetidor norte → vivienda 06, a 15,3 m. El orden cambia. La longitud total, en este grafo, no: los dos dan 870,7 m.

6. Dijkstra · camino desde la casa principal

El árbol dice qué enlaces existen. Dijkstra dice, si se elige una vivienda, qué secuencia acumula menos penalización desde la antena. Parte con 0 en la casa principal y con infinito en el resto.

// dijkstra.ts — sourceId es la antena. weight es attenuationUnits.
dist.set(sourceId, 0);

while (heap.size > 0) {
  const current = heap.pop();
  if (current.d > dist.get(current.id)) continue; // copia vieja de la cola
  for (const link of vecinos) {
    const next = current.d + weight(link.edge);   // suma metros penalizados
    if (next < dist.get(link.neighborId)) {
      dist.set(link.neighborId, next);
      prev.set(link.neighborId, { nodeId: current.id, edgeId: link.edge.id });
      heap.push({ id: link.neighborId, d: next });
    }
  }
}
Dijkstra corre sobre las 276 aristas, no solo sobre las 23 del árbol. Por eso el camino hasta una casa lejana puede ser un radio directo, aunque ese radio no esté en el árbol. reconstructPath arma la lista de casas. pathEdges arma la lista de enlaces.

7. Quién llama a los tres algoritmos

Un solo archivo encadena el modelo. El mapa y el diagrama solo leen lo que este contexto ya calculó.

const candidate = buildCandidateEdges(nodes);          // 276 distancias

const mstEdges = algorithm === "prim"

const result = dijkstra(nodes, candidate, "gw-principal", attenuationUnits);
